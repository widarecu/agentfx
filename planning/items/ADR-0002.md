# Architecture Decision Record (ADR)

ID: ADR-0002
Date: <YYYY-MM-DD>
Title: Repository structure, modular boundaries, and virtualenv policy

## Context
We need an extensible codebase where new features and providers have minimal blast radius. We also require reproducible, isolated development and CI to avoid dependency/version drift.

## Decision
- Adopt layered repository structure with dependency inversion:
  - src/agentfx/core: domain and policies (no I/O)
  - src/agentfx/adapters: broker, storage, observability implementations
  - src/agentfx/services: orchestration (ingestion, backtesting, paper runner)
  - src/agentfx/shared: config, types, helpers
  - src/agentfx/ui: portal (later)
- Define interfaces (protocols/ABCs) for broker, datastore, metrics; adapters implement these and are injected.
- Enforce virtual environments for all dev/test/build; no system Python.
- Use requirements.in/.txt and requirements-dev.in/.txt with pip-tools to manage and lock dependencies.
- Provide Makefile, tox, and pre-commit hooks to standardize workflows and checks.

## Alternatives
- Flat repo with ad-hoc modules; no interfaces. Rejected due to high coupling and change risk.
- Poetry/conda for env mgmt. Deferred; pip-tools + venv is simpler for MVP and CI.

## Consequences
- Clear extension points and lower change impact.
- Slight upfront overhead (interfaces, adapters, venv discipline) for long-term velocity.
- Reproducible installs and consistent CI checks.
